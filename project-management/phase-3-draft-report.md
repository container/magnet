# Phase 3 Report Structure

Purpose: concise working outline for the Phase III concept/report document.

Status: skeleton

Use this as a living document during workshops, validation interviews and prototype reviews. Keep final accepted requirements in `specs/platform/`.

---

## 1. Context

- Where the project is after Phase II
- What Phase III needs to validate
- What the current prototype/specs cover and do not cover
- UX designer role and responsibilities

## 2. Method

- Workshops D1-D5
- Moved interviews as validation interviews
- Prototype walkthroughs as validation/support method
- Decision tracking

## 3. User Groups And Roles

- User-group taxonomy
- Roles and permissions from the UX perspective
- Open access/privacy questions

## 4. User Journeys

- Key public, member, renter, event-organizer and admin journeys
- Validated needs, pain points and missing steps
- Operational process behind each journey

## 5. Platform Scope

- MVP / opening-critical
- Later phase
- External integration only
- Out of scope

## 6. IA And Content Structure

- Sitemap
- Main navigation
- Page/content types
- CMS-managed content
- Public/admin relationship

## 7. Data / Content Model

- Key content/data objects
- Required fields at concept level
- Relationships between content, users, spaces, events and reservations
- What is already covered in platform specs

## 8. Functionality Prioritization

- Master functionality list
- Priority matrix
- Dependencies and integrations
- Prototype/spec coverage

## 9. CGP / Identity Hierarchy

- DOM / MAG-NET / MOC / operator relationship
- Naming and navigation implications
- Rules for service differentiation

## 10. Decision Log And Open Decisions

- Decisions confirmed during Phase III
- Open decisions
- Owner / next step / deadline where known
- Impact on scope, prototype, specs or procurement

## 11. Recommendations And Next Steps

- Recommended platform concept
- Recommended MVP scope
- Open decisions before procurement
- Inputs needed for the next tender/specification

## M3 Requirement Check

- Sitemap
- Content sections / content structure
- User scenarios
- Draft platform scope
- Proposed platform structure
- Proposed additional functionality, where useful
- Alignment with M1/M2 findings
- Client review and written approval
